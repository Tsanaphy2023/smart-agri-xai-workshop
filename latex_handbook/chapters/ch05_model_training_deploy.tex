\chapter{การฝึกสอนโมเดลปัญญาประดิษฐ์และการประยุกต์ใช้งานจริง}
\label{ch:model_training_deploy}

การประมวลผลข้อมูลเกษตรกรรมในแปลงจริงจำเป็นต้องอาศัยโมเดลการเรียนรู้เชิงลึก (Deep Learning) ที่มีทั้งความแม่นยำสูงและขนาดกะทัดรัด สามารถประมวลผลบนอุปกรณ์ขอบ (Edge Device) หรือสมาร์ทโฟนของเกษตรกรได้โดยไม่ต้องพึ่งพาสัญญาณอินเทอร์เน็ตความเร็วสูงตลอดเวลา ในบทนี้จะอธิบายขั้นตอนการถ่ายโอนการเรียนรู้ (Transfer Learning) ด้วยสถาปัตยกรรม MobileNetV3 การจัดเตรียมท่อส่งข้อมูล การส่งออกโมเดลในรูปแบบ ONNX และการเชื่อมต่อเข้ากับระบบเว็บแอปพลิเคชัน

\academicsection{สถาปัตยกรรม MobileNetV3 สำหรับการประมวลผลบนอุปกรณ์ขอบ}
\label{sec:mobilenetv3_arch}

สถาปัตยกรรม MobileNetV3 เป็นโมเดลจำแนกภาพที่ได้รับการออกแบบและค้นหาโครงสร้างโครงข่ายโดยใช้เทคนิค Neural Architecture Search (NAS) ร่วมกับ NetAdapt algorithm เพื่อให้ได้ประสิทธิภาพการประมวลผลที่ดีที่สุดบนฮาร์ดแวร์ซีพียูเคลื่อนที่ (Mobile CPU) โดยมีคุณลักษณะเด่นสำคัญ 3 ประการ:

\begin{enumerate}
    \item \textbf{Inverted Residual with Linear Bottleneck:} การขยายมิติของชั้นสัญญาณด้วย $1 \times 1$ Convolution ก่อนเข้าสู่ Depthwise Separable Convolution และบีบอัดกลับด้วย Linear Bottleneck ช่วยลดจำนวนพารามิเตอร์และการคำนวณลงอย่างมหาศาล
    \item \textbf{Squeeze-and-Excitation (SE) Module:} การปรับน้ำหนักความสำคัญของแต่ละช่องสัญญาณ (Channel Attention) อย่างมีไดนามิก ช่วยเพิ่มขีดความสามารถในการตรวจจับรายละเอียดโรคพืชที่มีขนาดเล็ก
    \item \textbf{Hard-Swish Activation Function:} การใช้ฟังก์ชันการกระตุ้น $h\text{-swish}(x) = x \cdot \frac{\text{ReLU6}(x+3)}{6}$ ซึ่งให้คุณสมบัติความไม่เป็นเชิงเส้นใกล้เคียงกับ Swish ดั้งเดิม แต่คำนวณได้รวดเร็วและใช้พลังงานหน่วยประมวลผลต่ำกว่ามาก
\end{enumerate}

\academicsection{ท่อส่งข้อมูลและการเพิ่มพูนข้อมูลภาพ (Data Pipeline \& Precision ROI)}
\label{sec:data_pipeline}

ภาพถ่ายทางการเกษตรภาคสนามมักเผชิญกับความผันผวนของสภาพแวดล้อม เช่น แสงแดดจัด เงาตกกระทบ มุมกล้องที่เอียง หรือสิ่งกีดขวางในธรรมชาติ การฝึกสอนโมเดลจึงต้องประยุกต์ใช้เทคนิคการเพิ่มพูนข้อมูลภาพ (Data Augmentation) ร่วมกับกระบวนการครอบตัดเป้าหมายความแม่นยำสูง (Precision ROI Crop):

\begin{itemize}
    \item \textbf{Agri-Vision 2.0 Precision ROI Transform:} ก่อนเข้าสู่กระบวนการบีบอัดขนาด ภาพจะถูกสแกนด้วยอัลกอริทึม Bio-Spectral ExG \& Center Gaussian Prior เพื่อตัดเฉพาะพื้นที่ใบพืชหรือผิวดินเป้าหมายออกมา ทำให้โครงข่ายประสาทเทียมเรียนรู้เฉพาะสัญญาณที่มีนัยสำคัญทางชีวภาพ และขจัดสัญญาณรบกวนของฉากหลังออกอย่างถาวร
    \item \textbf{RandomResizedCrop (224x224):} สุ่มตัดและปรับขนาดภาพให้อยู่ระหว่างร้อยละ 80 ถึง 100 ของภาพต้นฉบับ เพื่อจำลองระยะการถ่ายภาพของเกษตรกรที่แตกต่างกัน
    \item \textbf{RandomHorizontalFlip \& RandomVerticalFlip:} การพลิกภาพแนวนอนและแนวตั้งด้วยความน่าจะเป็น 0.5 เพื่อรองรับการหมุนของใบพืชในแปลง
    \item \textbf{ColorJitter:} ปรับเปลี่ยนค่าความสว่าง (Brightness) ความคมชัด (Contrast) และความอิ่มตัวสี (Saturation) เล็กน้อย เพื่อจำลองสภาพแสงธรรมชาติในแต่ละช่วงเวลาของวัน
    \item \textbf{ImageNet Normalization:} ปรับสเกลค่าพิกเซลด้วยค่าเฉลี่ย $\mu = [0.485,\, 0.456,\, 0.406]$ และส่วนเบี่ยงเบนมาตรฐาน $\sigma = [0.229,\, 0.224,\, 0.225]$
\end{itemize}

สำหรับผู้เรียนที่ไม่เคยเขียนโปรแกรมมาก่อน สามารถปรับแต่งค่าสำคัญในเซลล์คำสั่งได้โดยอาศัยหลักคิดเชิงปฏิบัติ ดังนี้:
\begin{itemize}[leftmargin=1.2em, itemsep=3pt]
    \item \textbf{Epochs (รอบการเรียนรู้):} เปรียบเสมือนจำนวนรอบที่สมองกล AI นั่งอ่านทบทวนชุดภาพเพื่อจำแนกลักษณะ (ค่าแนะนำ 10--15 รอบ หากน้อยไป AI จะจำไม่ได้ หากมากไปอาจเกิดการท่องจำข้อสอบเดิม)
    \item \textbf{Batch Size (ขนาดกลุ่มภาพ):} จำนวนภาพที่ส่งเข้าไปปรับน้ำหนักพร้อมกันในหนึ่งวินาที (ค่าแนะนำ 16 ภาพ เพื่อความสมดุลของหน่วยความจำ)
    \item \textbf{Learning Rate (อัตราการปรับตัว):} ความเร็วในการก้าวเดินปรับตัวของเซลล์ประสาทเทียม (ค่าแนะนำ 0.001 เพื่อไม่ให้สมองกลปรับค่าน้ำหนักกระโชกโฮกฮากจนหลุดกรอบ)
    \item \textbf{Target ROI Crop (การตัดกรอบเป้าหมาย):} สั่งให้ตัดเฉพาะบริเวณสี่เหลี่ยมสีเขียวส่งเข้าเทรน เพื่อป้องกันไม่ให้โมเดลจำสิ่งที่ติดมาในฉากหลัง เช่น มือคน ก้อนหิน หรือขอบกระถาง
\end{itemize}
\end{academicNote}

\academicsection{โครงสร้างสคริปต์การฝึกสอน PyTorch และการเชื่อมต่อ Precision ROI}
\label{sec:pytorch_training}

ระบบได้ออกแบบสคริปต์การฝึกสอน \texttt{train\_custom\_soil\_model.py} ให้รองรับการปรับแต่งไฮเปอร์พารามิเตอร์ได้อย่างยืดหยุ่น โดยมีแฟล็ก \texttt{--enable\_roi\_crop} สำหรับเปิดใช้งานท่อส่งข้อมูล Agri-Vision 2.0 อัตโนมัติ:

\begin{tcolorbox}[title=\textbf{ตัวอย่างโค้ดท่อส่งข้อมูล Precision ROI และโครงสร้างโมเดล}]
\fontsize{8.5}{11}\selectfont
\begin{verbatim}
import torch
import torch.nn as nn
from torchvision import models, transforms
from roi_preprocessor import extract_target_roi

# 1. Custom Precision ROI Preprocessing Transform
def precision_roi_transform(img):
    try:
        np_img = np.array(img.convert('RGB'))
        roi, _ = extract_target_roi(np_img, mode='auto', pad_ratio=0.10)
        return Image.fromarray(roi)
    except Exception:
        return img

# 2. Composable Agri-Vision Pipeline
train_transforms = transforms.Compose([
    transforms.Lambda(precision_roi_transform),
    transforms.RandomResizedCrop(224),
    transforms.RandomHorizontalFlip(),
    transforms.ColorJitter(brightness=0.2, contrast=0.2),
    transforms.ToTensor(),
    transforms.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225])
])
\end{verbatim}
\end{tcolorbox}

ระบบทดสอบแบบโต้ตอบใน Google Colab รองรับการป้อนข้อมูลภาพ 3 มิติหลัก:
\begin{enumerate}
    \item \textbf{การเปิดกล้องอุปกรณ์สดผ่านโปรโตคอล WebRTC (Live Camera WebRTC):}
    เนื่องจาก Google Colab ประมวลผลอยู่บนคลาวด์เซิร์ฟเวอร์เสมือน จึงไม่สามารถเรียกคำสั่งเข้าถึงฮาร์ดแวร์เว็บแคมโดยตรงอย่าง \texttt{cv2.VideoCapture} ได้ ระบบจึงใช้เทคนิคการฉีดสคริปต์ JavaScript ผ่าน \texttt{IPython.display.Javascript} เพื่อเชื่อมต่อ \texttt{navigator.mediaDevices.getUserMedia} ของเว็บเบราว์เซอร์บนเครื่องผู้ใช้ (โน้ตบุ๊ก หรือสมาร์ทโฟน) นำเฟรมภาพวิดีโอแปลงเป็น Base64 Data URL และส่งกลับมาถอดรหัสเป็นไฟล์ภาพไบนารีบน Colab:
    \begin{equation}
        \text{Webcam Stream} \xrightarrow{\text{canvas.toDataURL}} \text{Base64 String} \xrightarrow{\text{b64decode}} \text{JPEG Buffer}
    \end{equation}

    \item \textbf{การอัปโหลดไฟล์ภาพจากเครื่องผู้ใช้ (Local File Upload):}
    เชื่อมต่อกับ \texttt{google.colab.files.upload()} ให้ผู้เข้าอบรมสามารถลากไฟล์ภาพถ่ายโรคพืชหรือภาพหน้าดินจริงจากโทรศัพท์หรือโฟลเดอร์ในเครื่องขึ้นสู่หน่วยความจำ Colab ได้ทันที

    \item \textbf{การสุ่มภาพจากชุดข้อมูลทดสอบ (Validation Dataset Sampling):}
    ดึงภาพจากชุดตรวจสอบความถูกต้อง (Validation Set) ที่โมเดลไม่เคยเห็นในกระบวนการเทรน เพื่อทดสอบความสามารถในการสรุปนัยทั่วไป (Generalization Ability)
\end{enumerate}

ภาพที่ผ่านการป้อนเข้ามาจะถูกส่งผ่านระบบ \textbf{Agri-Vision 2.0 Precision ROI} เพื่อตัดเฉพาะวัตถุเป้าหมายชีวภาพ ก่อนนำเข้าสู่โมเดลโครงข่ายประสาทเทียมเพื่อคำนวณค่าความน่าจะเป็นแบบซอฟต์แมกซ์ (Softmax Probability Distribution):
\begin{equation}
    P(y = c \mid \mathbf{x}) = \frac{\exp(z_c)}{\sum_{j=1}^C \exp(z_j)}
\end{equation}
พร้อมเรนเดอร์กราฟแท่งแนวนอน (Horizontal Top-$K$ Bar Chart) แสดงระดับความเชื่อมั่น (\%), ค่าพิกัดสี $L^*, a^*, b^*$, ดัชนีความชื้นคาดคะเน ($100 - L^*$) และดัชนีสีแดงดินลูกรัง ($R^2 / BG$) เพื่อให้ผู้เข้าอบรมเห็นผลลัพธ์เชิงฟิสิกส์อย่างรอบด้าน

\academicsection{การส่งออกโมเดลและการประยุกต์ใช้งานบนเว็บและสมาร์ทโฟน}
\label{sec:model_export_deployment}


เมื่อแบบจำลองได้รับการฝึกสอนในสภาพแวดล้อม Google Colab จนลู่เข้าสู่จุดเหมาะสม (Convergence) และมีค่าความแม่นยำสูงกว่า 92\% แล้ว ขั้นตอนสำคัญลำดับถัดไปคือการแปลงโมเดลให้อยู่ในฟอร์แมตที่เหมาะสมต่อการใช้งานจริงในแปลงเกษตร ดังแสดงในภาพที่ \ref{fig:colab_to_app_pipeline} ซึ่งจำแนกออกเป็น 2 เส้นทางหลัก:

\begin{enumerate}
    \item \textbf{เส้นทาง Web Application Dashboard (ONNX Format):}
    แปลงโมเดล PyTorch เข้าสู่มาตรฐาน Open Neural Network Exchange (\texttt{smart\_agri\_model.onnx}) ผ่านคำสั่ง \texttt{torch.onnx.export} โดยกำหนดให้แกนขนาดแบทช์ (Batch Size) เป็นไดนามิก เพื่อให้เซิร์ฟเวอร์ Streamlit และ FastAPI สามารถโหลดโมเดลผ่าน In-Process ONNX Runtime ได้โดยตรงโดยไม่ต้องติดตั้ง PyTorch หรือไดรเวอร์ GPU ขนาดใหญ่ มีความหน่วงในการประมวลผลต่ำกว่า 15 มิลลิวินาที
    
    \item \textbf{เส้นทาง Smartphone Mobile App (Quantized TFLite):}
    นำโมเดลเข้าสู่กระบวนการบีบอัดและควอนไทเซชัน (Weight Quantization) เพื่อแปลงเป็น TensorFlow Lite (\texttt{smart\_agri\_model.tflite}) ช่วยลดขนาดไฟล์จากเดิมกว่า 20 MB เหลือเพียง 4--6 MB จากนั้นนำไปบรรจุลงในโฟลเดอร์ \texttt{assets/models/} ของแอปพลิเคชัน Flutter เพื่อให้ชิปเร่งความเร็ว NPU/CPU ภายในสมาร์ทโฟนประมวลผลการวินิจฉัยโรคพืชและวิเคราะห์ภาพดินได้แบบออฟไลน์ 100\% ไร้สัญญาณอินเทอร์เน็ต
\end{enumerate}

\academicsection{การประยุกต์ใช้งานบนสมาร์ทโฟน iPhone (iOS) และ Android}
\label{sec:iphone_android_deploy}

แอปพลิเคชันสมาร์ทโฟนของระบบได้รับการพัฒนาขึ้นด้วย \textbf{Flutter Framework (Google)} ซึ่งมีสถาปัตยกรรม Cross-Platform รองรับทั้งระบบปฏิบัติการ iOS (iPhone และ iPad) และ Android จากฐานรหัสต้นฉบับเดียวกัน 100\% โดยสามารถเลือกแนวทางการส่งมอบได้ 2 รูปแบบหลัก:

\begin{enumerate}
    \item \textbf{การใช้งานแบบ Progressive Web App (PWA) บน Safari (iPhone):}
    ผู้ใช้งานสามารถเปิดเบราว์เซอร์ Safari บน iPhone ไปยัง URL ของ Web Dashboard จากนั้นแตะปุ่มแชร์และเลือก \textit{"เพิ่มไปยังหน้าจอโฮม" (Add to Home Screen)} ระบบจะติดตั้งไอคอนแอปบนหน้าจอโฮมและเปิดทำงานแบบ Standalone ไร้แถบที่อยู่เว็บ สามารถเรียกใช้งานกล้อง iPhone ผ่าน HTML5 Media Capture ได้ทันทีโดยไม่ต้องผ่านกระบวนการลงทะเบียนนักพัฒนา
    
    \item \textbf{การติดตั้งเป็น Native App ด้วยชิป Apple Neural Engine (ANE):}
    บนสมาร์ทโฟน iPhone ที่ใช้ชิปประมวลผล Apple Silicon (ตั้งแต่ A12 Bionic จนถึง A18 Pro) ระบบ \texttt{tflite\_flutter} สามารถเรียกใช้ Metal Performance Shaders (MPS) และ Neural Engine เพื่อประมวลผลโมเดล Quantized TFLite ได้ด้วยความหน่วงต่ำเพียง 10--18 มิลลิวินาที โดยแอปพลิเคชันได้รับการกำหนดสิทธิ์การเข้าถึงฮาร์ดแวร์ในไฟล์ \texttt{Info.plist} ไว้อย่างสมบูรณ์:
    \begin{itemize}
        \item \texttt{NSCameraUsageDescription:} สำหรับเปิดกล้องส่องวิเคราะห์โรคพืชและหน้าดิน
        \item \texttt{NSBluetoothAlwaysUsageDescription:} สำหรับการเชื่อมต่อโพรบวัดดิน RS485 ผ่านสัญญาณ Bluetooth Low Energy (CoreBluetooth)
        \item \texttt{NSPhotoLibraryUsageDescription:} สำหรับการเลือกภาพจากคลังภาพ
    \end{itemize}
    สำหรับการแจกจ่ายให้ผู้เข้าอบรม 50 คนในห้องเรียน สามารถส่งผ่านระบบ \textbf{Apple TestFlight} ด้วย Public Link เพื่อให้ผู้เรียนทุกคนกดติดตั้งแอปพลิเคชันลงบนเครื่อง iPhone ส่วนตัวได้ทันที
\end{enumerate}

\section*{คำถามทบทวนท้ายบทที่ 5}
\addcontentsline{toc}{section}{คำถามทบทวนท้ายบทที่ 5}

\begin{enumerate}
    \item จงอธิบายเหตุผลที่ต้องส่งออกโมเดล PyTorch เป็นฟอร์แมต ONNX แทนที่จะโหลดไฟล์น้ำหนัก \texttt{.pth} โดยตรงบนเว็บเซิร์ฟเวอร์
    \item การทำ Model Quantization สำหรับสมาร์ทโฟนมีข้อดีอย่างไร และส่งผลกระทบต่อความเร็วและความแม่นยำของโมเดลหรือไม่
    \item จงเปรียบเทียบสถาปัตยกรรม MobileNetV3 กับ ResNet-50 ในแง่ของจำนวนพารามิเตอร์และประสิทธิภาพบนอุปกรณ์ขอบ (Edge Devices)
    \item จงอธิบายขั้นตอนการนำไฟล์ \texttt{.tflite} ไปใช้งานในแอปพลิเคชัน Flutter ร่วมกับแพ็กเกจ \texttt{tflite\_flutter} แบบออฟไลน์
\end{enumerate}
